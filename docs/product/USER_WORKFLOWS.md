# User Workflows

Основной поток: создать/открыть аналитическое дело → импортировать результат независимо выполненного испытания R130SH → использовать предварительно заполненные исходные значения → дополнить недостающие сведения → выполнить анализ → выпустить документ. Дело допускается создать и до получения результата, но оно ничего не передаёт на стенд.

Для отдельной read-only проверки инженер открывает «Диагностика» → «Проверка контракта R130SH». Для production workflow он создаёт/открывает `.irproj`, переходит в «Результаты R130SH» и выбирает `.r130run`: Main разрешает ordinary file, Python повторно валидирует managed copy и атомарно регистрирует immutable source, inventory, projection и audit. После импорта инженер явно связывает source specimen с локальным Specimen и фиксирует выбор существенных source/analyst values; закрытие и повторное открытие возвращают тот же archive и provenance. Ни M03A, ни M03B не являются допуском к расчёту M04.

Impeller Reliability не готовит и не передаёт план в R130SH. Расчёты РБД/РПТ/ПМН являются внутренней последующей аналитикой проекта, а не контуром управления стендом.

Будущая `TestCampaign` группирует уже импортированные запуски для сравнения нескольких режимов одного образца, образцов одной партии или повторных испытаний. Она не предшествует стендовому запуску.

M02.2A добавляет редактируемые сведения дела: заказчика, модели рабочих колёс и физические образцы. M03B хранит исходные значения R130SH отдельно от этих дополнений; копирование выбранного значения разрешено только в новую/пустую analyst entity после явного подтверждения и не меняет source snapshot.

M02.2B добавляет раздел «Документы дела». Инженер создаёт metadata-only запись или выбирает разрешённый локальный файл, связывает документ с несколькими моделями/образцами либо оставляет без связей для применимости ко всему делу. Main владеет системным диалогом, Python проверяет тип/размер/сигнатуру, потоково копирует файл в `assets/documents`, вычисляет SHA-256 и атомарно регистрирует управляемую копию. Исходный абсолютный путь не сохраняется и не показывается Renderer.

Файл можно прикрепить к metadata-only документу только один раз. Новая фактическая редакция создаётся новым документом; старую запись инженер при необходимости архивирует. Проверка возвращает `verified`, `missing`, `modified` или `verification_error`; проблема одного файла не мешает открыть проект и не меняет сохранённый hash автоматически. Открытие управляемой копии разрешено только после повторной проверки containment и SHA-256.

Смена раздела, выбранного документа, attach, archive/restore, закрытие/открытие проекта и restart worker используют один draft guard. Validation, conflict и transport failure сохраняют ввод. Manual backup содержит только `project.sqlite`; для полного переноса инженер закрывает проект и копирует весь каталог `*.irproj`.
