# Windows Setup

Единственная внешняя поставка — полный офлайн Windows x64 NSIS `ImpellerReliabilityCalc-<version>-Setup-x64.exe`. Заказчик копирует его из общей сетевой папки на свой ПК и запускает локально. Установка строго для текущего пользователя, без выбора all-users и повышения прав. Политика Windows может запретить неподписанную программу; Setup не обходит ограничения рабочего места. Python, Node и R130SH клиенту не требуются.

## Идентичность и программный комплект

Стабильны `appId=com.vitalyvlasov.impellerreliability`, `productName=Impeller Reliability` и `ImpellerReliabilityCalc.exe`. Единственный источник application version — `apps/desktop/package.json`: из него собираются Main, package/EXE и Setup. Выпускаются стабильные числовые версии `major.minor.patch`; версии worker, IPC, формата дела и инженерного алгоритма — отдельные контракты.

Установленная программа — обычный каталог с Electron `app.asar`, ресурсами и PyInstaller onedir в `resources/python-worker`. `afterPack` применяет и перечитывает fuses, проверяет manifest/SHA-256 и выполняет worker self-test; Main проверяет worker перед запуском. Вложенный onefile не используется. `win-unpacked` остаётся диагностическим payload.

NSIS переиспользует свою регистрацию и прежний путь. Небольшой `resources/installer.nsh` добавляет политику версии и ожидания процессов через системный Windows PowerShell. Отсутствуют online updater, update feed, differential delivery, сервер, служба, автоматический rollback и публикация Releases.

Используется штатный ZIP-extractor с проверкой результата и ненулевым кодом по умолчанию до успешного завершения Setup. В locked builder 26.15.3 путь извлечения 7z после ошибки записи может игнорировать отказ и объявить успех; проверка эксклюзивно заблокированного `app.asar` защищает от этого результата. Минимальный `patches/app-builder-lib@26.15.3.patch` закреплён точной версией/hash через pnpm и содержит два изменения у владельца шаблонов: удаляет безусловное копирование Setup в неиспользуемый updater-кэш и добавляет `/SD IDOK` к сообщению об ошибке ZIP, чтобы silent-запуск завершался отказом без ожидания диалога. При обновлении builder каждую часть проверяют отдельно: первую удаляют при штатной возможности отключения кэша либо отдельном решении добавить updater, вторую — после штатного исправления silent-ошибки ZIP. Registration и uninstall не меняются. Runtime-очистки существующих кэшей нет; elevation helper не включается.

## Установка, обновление и удаление

Setup разрешает более новую и ту же версию. Старая версия отклоняется до удаления/замены текущей; неизвестная версия существующей регистрации также останавливает установку. Сравнение числовое: `1.10.0 > 1.9.0`. Равная переустановка восстанавливает файлы программы. Исправление неудачного выпуска передаётся новой версией.

При работающем приложении Setup остаётся открытым: пользователь сохраняет работу, закрывает все относящиеся к установке окна и выбирает «Повторить» либо отменяет установку. Установщик и встроенный деинсталлятор не завершают процессы. Проверяется executable path всего installation tree, включая worker без живого родителя; процессы соседней установки не затрагиваются. Ошибка наблюдения блокирует замену. Повторная проверка непосредственно перед удалением сохраняет исходный интерактивный режим, даже когда штатный шаблон NSIS скрывает свой экран выполнения. Silent-запуск при занятых файлах возвращает отказ и не подтверждает интерактивный Retry/Cancel.

Удаление через Windows удаляет программу, ярлыки и её регистрацию, сохраняя профиль, recent list и внешние дела. Параметр удаления app data отвергается. Перед обновлением вручную удалять программу не нужно. После контролируемого сбоя повторно запускается полный Setup; универсальная атомарность при отключении питания не обещается.

## Данные и совместимость

Electron `userData` зависит от неизменного имени приложения и находится вне installation tree. Main хранит там `state/recent-projects.json` и инфраструктурное состояние. Smoke использует отдельный явно заданный профиль, фиксируя package/runtime version.

Диалог создания предлагает Документы. Main отклоняет create/open/recent-open внутри installation/resources tree, включая junction, до обращения к worker. Если такое дело уже существует, пользователь закрывает его во всех окнах, вручную переносит **весь** каталог `.irproj` в обычную пользовательскую папку и открывает снова. Автоматического поиска/переноса/очистки дел нет.

Обновление программы сохраняет текущий формат дела и читает историю без пересчёта. Невыпущенные промежуточные схемы не получают совместимость. При первой фактической клиентской передаче сохраняются исходный SHA, версия и SHA-256 Setup, контрольное дело из этого runtime и сводка readback. Закрытие задачи установщика само по себе не объявляет версию опубликованной.

Первое изменение **опубликованного** формата потребует распознавания и проверки исходной версии, объяснения последствий при первом открытии, выбора «Обновить дело» / «Отмена», проверенной резервной копии всех изменяемых данных после согласия, затем преобразования и проверки результата. Отмена и ошибка backup запрещают преобразование. Нужен E2E на деле реального предшественника. Сейчас новая schema и неиспользуемый migration API/UI не вводятся. SQLite backup не является полной копией дела с вложениями и архивами; для полной копии закрывают дело и копируют весь `.irproj`.

## Сборка и проверка

Самостоятельные package-команды сначала проверяют/собирают worker и приложение; сбой prerequisites останавливает упаковку. Полный gate переиспользует свежие сборки: Electron E2E → worker onedir/self-test → WinUnpacked smoke → Setup → installed lifecycle. Команды и выбор проверок принадлежат [политике тестирования](../../tests/AGENTS.md).

`scripts/smoke/installer.ps1` требует отсутствующей установки/ярлыков, отказывает при чужой регистрации и создаёт собственный каталог в ignored evidence. Он собирает два настоящих выпуска: текущий N и следующий patch N+1 из тех же исходников, временно меняя единственный источник версии и гарантированно восстанавливая metadata и текущий Electron build. Worker переиспользуется при неизменных входах. Предыдущий тестовый payload содержит лишний файл для проверки его удаления при обновлении; тестовые Setup не передаются заказчику.

N создаёт representative дело, managed PDF, досье, producer-generated РБД/РПТ/ПМН и первичные материалы, immutable snapshots и recent state. N+1 читает именно эти данные: полные DTO через worker, историю/input/result/provenance, хеши immutable файлов и профиль. Readback не вызывает create/import/calculation и не сравнивает весь Chromium profile или изменяемый SQLite-файл побайтно. Сохраняются process-tree no-TCP/no-orphan проверки. Lifecycle проверяет same-version repair, отказ downgrade, uninstall/reinstall и повторный Setup после ошибки извлечения при эксклюзивной блокировке `resources/app.asar`.

Обязательный UI-проход: открыть дело и оставить dirty draft → запустить Setup → «Повторить» при живом приложении → отменить, убедившись, что черновик/процессы сохранились; повторить с сохранением и штатным закрытием → «Повторить» → reopen. Проверить несколько окон/разные дела и оставшийся worker; затем удаление через Windows при работающем приложении. Нужны реальные диалоги. Проверка расположения проходит create/open/recent-open через установленное приложение. Evidence содержит SHA/снимок исходников, версии, хеши Setup, ОС и исходы; недоступное наблюдение не объявляется успешным.

## Передача выпуска

Разработчик повышает application version перед фактическим выпуском, собирает и проверяет Setup, сохраняет известный рабочий артефакт и его сведения, вручную копирует новый Setup в LAN share. Заказчик копирует файл локально, сохраняет работу, закрывает приложение, запускает Setup и продолжает работу с прежними делами. Версия доступна в диагностике и регистрации Windows. Подпись пока не обязательна; пробный запуск на целевом рабочем месте входит в передачу. GitHub Quality выполняет static/unit/build/E2E; установка проверяется локальным packaging gate без автоматической публикации.
