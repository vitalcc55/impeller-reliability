# IPC Protocol

Один долгоживущий worker; UTF-8 JSONL stdin/stdout; protocol v1. Request содержит `requestId`, конкретную `operation`, `revision`, `deadlineMs` и operation-specific `payload`. Response возвращает те же `requestId` и `revision`, затем operation-specific `result`/evidence/warnings либо typed error. Main связывает ответ с pending operation и применяет `RevisionGate`; несовпавшая revision отклоняется.

M01.1 allowlist: `system.handshake`, `system.ping`, `system.shutdown`, `storage.health`. TypeScript `WorkerOperationMap` и Python discriminated request union валидируют payload/result каждой операции; generic execute и `Record<string, unknown>` для известных результатов отсутствуют. Message limit — 1 MiB, domain deadline ≤30 s, неизвестные операции и лишние payload fields отклоняются, stack trace не передаётся Renderer.

Worker lifecycle передаётся отдельно через узкое событие status changed. Preload предоставляет `getStatus`, `ping`, controlled `restart`, `openLog` и типизированный close handshake: delivery acknowledgement, confirm или cancel. Electron Main остаётся единственным владельцем состояния закрытия; произвольных IPC channel нет.

M02.1 добавляет operation-specific `project.create`, `project.open`, `project.close`, `project.getOverview`, `project.updateMetadata` и `project.createBackup`. Путь существует только в create/open payload Main → worker; остальные операции работают с активной ProjectSession. Renderer-facing `project.create/open` сами запускают системный диалог Main, а отмена возвращается typed `cancelled`.

Проектные ошибки: `project_locked`, `corrupt_project`, `incompatible_schema`, `revision_conflict`, `storage_error`, `timeout`. Для каждой operation задана пара `domainDeadlineMs < transportTimeoutMs`. Worker проверяет domain deadline до stateful commit и внутри SQLite backup progress callback. Если transport timeout всё же наступил для stateful project operation, Main завершает worker: поздний ответ не применяется, скрытая ProjectSession и удерживаемый OS lock невозможны. Response echo revision и pending request gate применяются без изменений.

M02.2A добавляет `caseCustomer.get/upsert`, `wheelModel.create/list/get/update/archive/restore` и `specimen.create/list/get/update/archive/restore`. Операции работают только с активной ProjectSession, не принимают путь и возвращают detail/list DTO с entity `recordRevision` и completeness warnings. `wheelModel.create` и `specimen.create` получают заранее созданный UUID v4: повтор той же команды после потери transport-ответа возвращает ту же запись, а не создаёт дубликат. Записывающие команды используют прежнюю bounded timeout policy; list/get проверяют domain deadline до и после SQLite query и не завершают worker при transport timeout. Новые typed errors: `entity_not_found`, `entity_archived`, `entity_in_use`, `duplicate_entity` и `validation_error`.

M02.2B добавляет worker operations `caseDocument.create/createWithFile/list/get/update/attachFile/verifyFile/archive/restore/resolveFile`. Renderer-facing Preload публикует те же операции, кроме внутреннего `resolveFile`: вместо него `openFile` просит Main повторно проверить registry containment/existence/SHA-256 и только затем вызвать `shell.openPath`. Renderer createWithFile/attach не содержат path; Main владеет dialog, выполняет предварительный gate и внедряет `sourcePath` только в worker payload. Detail DTO не содержит source/absolute/stored path. Stateful create/update/attach/archive/restore проверяют deadline только до commit; после commit возвращается однозначный result, а transport timeout завершает worker и требует revision-checked reattach.

Document errors: `duplicate_document_content`, `file_already_attached`, `unsupported_file_type`, `file_too_large`, `file_missing`, `file_integrity_mismatch` плюс общие entity/revision/validation/cancelled/timeout/storage codes. Contract/internal/OS details нормализуются на границе; stderr не содержит исходный document path, stack trace Renderer не получает.
