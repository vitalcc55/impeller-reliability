# Threat Model

Assets: project DB, immutable imports, reports, source documents and calculation provenance. Trust boundaries: untrusted renderer content, user-selected files, Main↔worker JSONL, external R130SH packages. Primary threats: renderer privilege escalation, generic IPC, worker substitution, ZIP traversal/bombs, contract confusion, CSV injection, stale response, data tampering and orphan processes. Controls are split across Electron hardening, integrity-checked worker, schema/checksum validation and immutable snapshots.

M02.1 controls project-path confusion by allowing create/open selection only in Main; recent paths are Main-owned allowlisted entries, но выбранный контейнер всё равно недоверенный. Python отклоняет отсутствующие, связанные и структурно неверные reserved paths, читает manifest не более 4 KiB и выполняет read-only SQLite validation (`application_id`, schema, migration ledger, projectId и metadata/audit evidence). Чисто закрытая база проверяется immutable; при наличии непустого WAL используется обычное read-only открытие, чтобы учесть уже зафиксированное состояние после аварийного завершения. Только затем worker захватывает OS lock и открывает SQLite на запись. Invalid/newer/schema-tampered SQLite не получает migration/backup, а atomic staging предотвращает частичный новый проект.

Timestamp-поля недоверенного manifest/SQLite не считаются безопасными строками: Python проверяет точный UTC-формат с миллисекундами, реальную календарную дату, порядок metadata/audit и совпадение project-created evidence до открытия сессии. TypeScript повторяет формат на IPC boundary, поэтому crafted дата не достигает renderer formatting как runtime exception.

Main↔worker transport зеркалит последовательную обработку JSONL: одновременно отправляется одна операция, ещё одна может ожидать, дальнейшие отклоняются backpressure; deadline начинается при dispatch, а не при ожидании в Main. Graceful shutdown и controlled restart закрывают приём новых запросов, дренируют принятую bounded-очередь и затем отправляют `system.shutdown`; final shutdown отменяет пересекающийся restart, поэтому lifecycle не обходит Python cleanup и не создаёт replacement/orphan worker. `SIGKILL` остаётся аварийной реакцией на protocol violation или indeterminate transport timeout, а не обычным shutdown path.

Активная злонамеренная подмена файлов другим процессом того же Windows-пользователя во время уже начатой операции не входит в модель угроз локального однопользовательского продукта. Приложение не содержит повторных identity-проверок, custom SQLite VFS или ACL-подсистемы для такого сценария.

M02.2B рассматривает выбранный документ как недоверенный. Renderer не передаёт path; Main получает его из системного dialog, не сохраняет и не логирует, выполняет только первичный extension/size/regular-file gate. Python повторяет gate, проверяет PDF/Office/image magic или UTF-8 text, нормализует extension, копирует потоково в project-owned staging, считает SHA-256 и публикует файл атомарным rename. В SQLite и audit сохраняется только POSIX path внутри `assets/documents/<uuid>/`; UPDATE/DELETE file row запрещены triggers.

При list/update/archive/restore Python всегда заново выполняет registry-derived containment и `lstat`; cached hash verdict применяется только при совпадении текущих `size` и `mtime_ns` с физической сигнатурой последней полной проверки. При resolve/get/verify Python дополнительно заново вычисляет SHA-256. Missing/modified copy получает локальный integrity status и не открывается; сохранённый hash не меняется. Orphan staging имеет узкое имя/расположение, не считается зарегистрированным доказательством и очищается при следующем открытии. Полноценный antivirus, MIME framework, parser, OCR, преднамеренная подмена с восстановлением всех stat-атрибутов и защита от злонамеренного same-user TOCTOU не входят в локальную однопользовательскую модель.
