# Threat Model

Assets: project DB, immutable imports, reports, source documents and calculation provenance. Trust boundaries: untrusted renderer content, user-selected files, Main↔worker JSONL, external R130SH packages. Primary threats: renderer privilege escalation, generic IPC, worker substitution, ZIP traversal/bombs, contract confusion, CSV injection, stale response, data tampering and orphan processes. Controls are split across Electron hardening, integrity-checked worker, schema/checksum validation and immutable snapshots.

M02.1 controls project-path confusion by allowing create/open selection only in Main; recent paths are Main-owned allowlisted entries, но выбранный контейнер всё равно недоверенный. Для existing `.irproj` Python читает strict manifest, отклоняет reparse/symlink/junction и hard-linked reserved files, выполняет immutable read-only SQLite probe (`application_id`, schema, projectId), затем захватывает OS lock, повторно сверяет file identity и только после этого разрешает write connection, WAL, migration и backup. Invalid/newer/linked SQLite не получает lock, WAL/SHM, backup или изменение mtime. Atomic staging предотвращает частичный новый проект.

Остаточный TOCTOU: stdlib `sqlite3` не принимает уже проверенный Windows file handle и не предоставляет custom VFS, поэтому злонамеренный same-user процесс теоретически может заменить путь между последней identity-проверкой и внутренним SQLite access. Повторная проверка до первой разрешённой записи, non-creating `mode=rw`, OS lock и запрет reparse/hard links существенно сужают окно, но абсолютная защита потребовала бы отдельной ACL/directory ownership policy или собственного VFS, которые не входят в M02.1. Root/ancestor reparse points не запрещаются автоматически, чтобы не блокировать осознанно выбранные OneDrive/network-backed каталоги; mutable reserved descendants обязаны быть обычными локально адресуемыми объектами.
