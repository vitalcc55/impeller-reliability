# Threat Model

Assets: project DB, immutable imports, reports, source documents and calculation provenance. Trust boundaries: untrusted renderer content, user-selected files, Main↔worker JSONL, external R130SH packages. Primary threats: renderer privilege escalation, generic IPC, worker substitution, ZIP traversal/bombs, contract confusion, CSV injection, stale response, data tampering and orphan processes. Controls are split across Electron hardening, integrity-checked worker, schema/checksum validation and immutable snapshots.

M02.1 controls project-path confusion by allowing create/open selection only in Main; recent paths are Main-owned allowlisted entries, но выбранный контейнер всё равно недоверенный. Для existing `.irproj` Python сначала отклоняет reparse/symlink/junction и hard-linked manifest, сверяет identity открытого дескриптора и читает не более 4 KiB, затем выполняет immutable read-only SQLite probe (`application_id`, version-specific schema objects, migration ledger, projectId и полная metadata/audit evidence chain с каноническими event UUID). После этого worker захватывает OS lock, повторно сверяет file identity и весь contract до WAL и только затем разрешает migration/backup. Invalid/newer/linked/schema-tampered SQLite не получает lock, WAL/SHM, backup или изменение mtime. Atomic staging предотвращает частичный новый проект.

Timestamp-поля недоверенного manifest/SQLite не считаются безопасными строками: Python проверяет точный UTC-формат с миллисекундами, реальную календарную дату, порядок metadata/audit и совпадение project-created evidence до открытия сессии. TypeScript повторяет формат на IPC boundary, поэтому crafted дата не достигает renderer formatting как runtime exception.

Main↔worker transport зеркалит последовательную обработку JSONL: одновременно отправляется одна операция, ещё одна может ожидать, дальнейшие отклоняются backpressure; deadline начинается при dispatch, а не при ожидании в Main. Graceful shutdown и controlled restart закрывают приём новых запросов, дренируют принятую bounded-очередь и затем отправляют `system.shutdown`; final shutdown отменяет пересекающийся restart, поэтому lifecycle не обходит Python cleanup и не создаёт replacement/orphan worker. `SIGKILL` остаётся аварийной реакцией на protocol violation или indeterminate transport timeout, а не обычным shutdown path.

Остаточный TOCTOU: stdlib `sqlite3` не принимает уже проверенный Windows file handle и не предоставляет custom VFS, поэтому злонамеренный same-user процесс теоретически может заменить путь между последней identity-проверкой и внутренним SQLite access. Повторная проверка до первой разрешённой записи, non-creating `mode=rw`, OS lock и запрет reparse/hard links существенно сужают окно, но абсолютная защита потребовала бы отдельной ACL/directory ownership policy или собственного VFS, которые не входят в M02.1. Root/ancestor reparse points не запрещаются автоматически, чтобы не блокировать осознанно выбранные OneDrive/network-backed каталоги; mutable reserved descendants обязаны быть обычными локально адресуемыми объектами.
