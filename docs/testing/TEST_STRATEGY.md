# Test Strategy

## Владельцы проверок

| Контур | Ответственность |
| --- | --- |
| TypeScript / Node | Runtime contracts, path/revision boundaries, queue/deadlines/drain, draft/reconciliation logic. Настоящий child process остаётся там, где проверяются JSONL и lifecycle. |
| React / happy-dom | Два DOM-файла проверяют materials и imported-run interactions: pending, dirty, stale answers, accessible states. Остальные Vitest-файлы работают в Node; параллелизм ограничен четырьмя workers. |
| Python unit/integration | Точные расчёты и независимые golden values, ZIP/security/streaming, SQLite transactions, audit, immutable provenance, retry и reopen/corruption. |
| Electron E2E | Реальные Main → sandboxed Preload → worker → SQLite сценарии и пользовательские решения. Матрицы низкоуровневых ошибок остаются у владельца, существенные GUI error/dirty/restart/close paths сохраняются. |
| Packaged smoke | Настоящие WinUnpacked и Portable EXE, bundled worker, fuses/CSP/integrity, persistence/import/calculations/materials, отсутствие TCP и orphan worker в собственном process tree. |

Проверки наблюдают контракт и существенные границы, а не устройство fixtures, внутреннюю структуру тестов или декоративные элементы. Не добавляются тесты самого тестового контура. Фиксированные DEV-ответы preview не являются доказательством расчётов или persistence: unit оставляет режимы ready/unavailable, Browser проверяет синтетические сценарии, а производственные гарантии принадлежат Python/Electron/packaged checks. Ошибки обязательного process/TCP observation завершают smoke с отказом; штатное отсутствие сокетов получается из единственного общего TCP snapshot, отфильтрованного в памяти по собственным PID.

В полном `pnpm verify -- --IncludePackaging` приложение и worker собираются по одному разу в текущем запуске. Проверенный свежий WinUnpacked служит входом Portable через штатный `--prepackaged`; оба реальных smoke обязательны, compression не меняется. Standalone `pnpm package:win-unpacked` и `pnpm package:portable` самостоятельно проверяют и собирают prerequisites. PyInstaller исключает dev-only analysis/testing plugins, сохраняя runtime зависимости и self-test.

Изоляция тестов, существующие дедлайны, нулевые retries и Python branch coverage gate 85% сохраняются. Фактическое подтверждение даёт текущий запуск, а не количество тестов или отдельный status-документ. Общая подготовка файла/проекта допустима только при сохранении независимых начальных условий: cache-invalidation scenarios заново prime verified state перед каждой операцией, а metadata mutations проверяются в свежем repository. При целевых Python-запусках `--no-cov` исключает бессмысленную оценку общего coverage по одному файлу; полный gate всегда измеряет branch coverage.

Project storage Python tests доказывают atomic create, кириллицу/пробелы, close/reopen, optimistic revision, evidence audit только по изменённым полям, канонические UUID v4 entity events, audit rollback, corruption/newer schema без записи, bounded manifest с deadline, exact schema/evidence contract, timeout cleanup нового manual SQLite backup, закрытие connection после WAL failure и реальный lock contention с освобождением после crash. Первая публикуемая schema v1 создаётся целиком; migration backup не создаётся без поддерживаемого predecessor, а future migration harness проверяется синтетической следующей версией. Vitest доказывает TypeScript boundary, последовательный dispatch/backpressure/deadlines и drain перед shutdown/restart. Electron E2E проверяет dirty draft, reattach/local discard, Main-owned close state, crash после close acknowledgement, завершение принятого save перед закрытием и create → update → close → reopen; packaged smoke повторяет persistence-сценарий. Browser preview остаётся синтетическим и не считается проверкой persistence.

Analyst dossier tests покрывают Customer/WheelModel/Specimen CRUD, canonical decimal/date/project UUID versions 1–8 против UUID v4 entity IDs, incomplete warnings, no-op/conflict, archive restrictions, tamper-resistant entity audit и close/reopen persistence. Create retry с тем же UUID v4 не создаёт дубликат; integrity tests отклоняют no-op audit revision и активный образец под архивной моделью. Electron E2E проходит customer → wheel model → specimen → archive/restore → reopen и общий dirty lifecycle для навигации, архивного действия, restart и window close. Packaged smoke после reopen сверяет идентификаторы, связи, значения и revisions через bundled worker.

M02.2B Python tests покрывают metadata-only/createWithFile, idempotent create/attach retry, single attach, duplicate content, metadata/applicability/no-op/conflict, archive/restore, allowlist/size/PDF/Office/image/UTF-8 signatures, streaming SHA-256, injected deadline/failure cleanup, staging recovery, missing/modified file, resolve containment, audit reconstruction и open project при локальной file problem. Integrity-cache regressions проверяют fresh `lstat`, delete, same-size rewrite с новым `mtime_ns`, reparse, update/archive/restore, close/reopen и отсутствие повторного SHA-256 на неизменённом list-path. Отдельная reopen-матрица доказывает, что changed/no-op/conflict/update/archive/restore/entity-archived не запускают SHA-256 под коротким stateful deadline, а authoritative hash остаётся у `get/verify/open`. Zod/Pydantic tests доказывают exhaustive operation/result/error maps и отсутствие absolute/source/stored path в Renderer DTO. Main-owned deterministic seam доказывает, что dialog cancellation и rejection различаются как `cancelled`/`storage_error`, Promise не отвергается и worker request не отправляется; нативное окно Windows не автоматизируется. Electron E2E проходит model+specimen → document+file → applicability → verify/open → update → archive/restore → close/reopen, file dialog cancellation/duplicate/unsupported type, metadata-only/attach, missing/modified с недоступным открытием потерянного файла, dirty navigation/restart/window close/detached discard, keyboard/focus и clean console.

M03A offline tests фиксируют exact synthetic contract snapshot и drift hashes; deterministic builder создаёт согласованные package только во временном каталоге и не называется golden. Python matrix покрывает UUID v4/v7 separation, strict ZIP paths/flags/methods/local-central/ZIP64/descriptors/gaps, фактические raw stream size/CRC/SHA-256, manifest/inventory, UTF-8/JSON/JSONL/CSV bounds, bounded finite decimal scalars frozen plan до арифметики, frozen shapes/values, honest coverage gaps, finding cap/redaction, source change, one-job idempotency/atomic replacement/cancel/discard/shutdown и отсутствие Project/SQLite/audit writes. TypeScript проверяет exhaustive maps, report/job invariants, safe numeric/string projection, path secrecy и polling adapter. Electron E2E проходит dialog cancel/reject → valid/invalid/long package → progress/verdict → restart/cancel/clear/focus → 640 px → close active job/no orphan; Browser QA подтверждает ready/unavailable, clean console и reflow. WinUnpacked/Portable smoke валидирует synthetic candidate bundled worker без extraction tree, TCP и Project mutation.

M03B cross-repository gate фиксирует exact R130SH M9a commit, index и все 21 producer packages/18 scenarios. Python acceptance проводит каждый archive через production import job, сопоставляет authored expectations с importer result, persisted registry/inventory/projection и reopen state; отдельно доказывает no-op/conflict/revision series, final/diagnostic partial, shared/distinct specimen identity, immutable triggers, whitelisted resolution/no overwrite, orphan cleanup, cancel/lost response и missing/modified source. Vitest проверяет exhaustive import operation maps, source/local UUID separation, job invariants, Main-only path injection и preview polling/binding. Electron E2E доказывает representative final create/open → import → progress/detail → bind/resolve → close/reopen и отдельное явное подтверждение diagnostic partial; остальные низкоуровневые crash/integrity paths принадлежат Python/TypeScript gates. WinUnpacked/Portable smoke повторяет один producer RBD import/reopen через bundled runtime и проверяет CSP/fuses/no TCP/no orphan/no external Python/no extraction tree. Полная матрица 21 packages остаётся Python acceptance, а не дублируется в packaged smoke. UI проверяется на Windows desktop 1280×720 / 1536×864 / 1920×1080; mobile/640 px не являются поддерживаемой поверхностью M03B.

M04A.1 добавляет exhaustive pure-owner matrix для шести disposition combinations, marker mismatch, unknown enum и accepted elapsed presence; production validator tests пересчитывают каждую строку Decimal-потока, переходы сегментов и accepted summary после полного обновления manifest/checksums/source snapshot. Synthetic `diagnostic_partial + resume_available=true` проходит production import и close/reopen. Existing integration tests повторно доказывают exact retry/no duplicate audit и same revision/different SHA conflict, а M04A regression сохраняет `acceptedElapsedS` в result evidence при `FailureObservation.durationS = NULL`. Отдельный snapshot gate продолжает проверять bytes, Git blobs, outer SHA-256 и package-index всех 21 frozen M9a packages.

M04B Python unit/integration покрывает classification/endpoint matrix, canonical decimal/count bounds и безопасное отклонение exponent до `Decimal`, failure без metric, interval без скрытой подстановки, документный snapshot, foreign evidence, immutable chains, доступность observation history старше первого окна из 50 версий, stale/exact/conflicting retry, dataset eligibility/include-exclude, уникальность included Specimen/source run, rollback и reopen corruption. Keyset tests доказывают page bounds, stable cursor и late insert isolation; producer и consumer измеряют UTF-8 JSONL bytes. TestExecution фиксирует WheelModel при materialization, поэтому изменение карточки Specimen не меняет историческую область.

Zod/Pydantic/dispatcher/Main/Preload tests проверяют exhaustive M04B operation maps и bounded inputs/results. Browser preview проверяет ready/unavailable, draft/error/restart и defensive reflow, но persistence не доказывает. Electron E2E через реальный worker/SQLite проходит import/binding/materialization → explicit observation → included/excluded dataset → следующая версия → close/reopen; packaged smoke подтверждает тот же контракт в поставке. Expected classification/membership синтетических сценариев заданы тестом независимо от production policy helper.

Первый расчёт РБД проверяется отдельно от статистической выборки: pure Python тесты используют независимые ожидаемые A/B/C, рациональную арифметику, периодическую дробь, пределы и точный `floor` около целочисленной границы. Интеграция проверяет чтение выбранного bounded plan member из exact managed archive, source/manual provenance, применимость таблицы 3, audit/rollback, exact/conflicting retry, историю старше первой страницы и отказ при повреждении снимков на reopen. Граничные тесты сохраняют импортированную числовую лексему до 128 символов, отличая её от более узкого канонического входа; resealed-тесты меняют вложенные поля результата и пересчитывают hash/audit, чтобы доказать структурный отказ уже при `project.open`, без запуска формул. Pydantic/Zod и process tests проверяют четыре узкие операции и предел UTF-8 JSONL. Browser preview проверяет только synthetic ready/unavailable, роли, focus и reflow; production Electron E2E проходит импорт → явный выбор входов → сохранение → чтение того же hash после reopen. WinUnpacked и Portable smoke используют frozen пакет с `1500.3` требуемых циклов против `1501` циклов producer target и через bundled worker сверяют сохранённый расчёт после reopen. Ни preview, ни smoke не заменяют полную матрицу Python owner.

WCAG 2.2 AA — engineering target, а не вывод одного сканера. Automated semantic/axe checks находят часть дефектов; Browser/Electron дополнительно проверяют keyboard-only, focus order/restoration, status/alert semantics, reduced motion и narrow reflow. NVDA, Narrator, Windows High Contrast и DPI/text scaling являются обязательным manual release evidence перед production release, когда реальные расчётные таблицы и графики уже существуют.
